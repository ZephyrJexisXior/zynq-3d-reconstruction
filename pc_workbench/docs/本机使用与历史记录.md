# FPGA 建模工作台

本机桌面入口：双击桌面 **FPGA 建模工作台**，或本目录 `启动建模.cmd`。界面运行在本机；新版安装地址为 `http://127.0.0.1:8795`（默认配置模板使用 8790），使用 Edge 独立窗口；不是需要聊天记录才能运行的程序。

## 使用顺序

1. 启动后自动检测有线网卡、电脑接收 IP、USB 串口、UDP 端口和 GPU。红色错误必须按提示处理；有线 IP 默认沿用板端实际发送目标 `192.168.2.1`，板端 IP 为 `192.168.2.99`，本机当前 UDP 为 `5012`（旧固件为 `5002`）。界面可修改电脑端接收配置，但不会替你改板端目标或网卡地址。
2. 检测通过后点击「开始接收照片」，再按正常流程操作开发板。只监听 FPG3/FPG4 等现有协议，不自动触发拍照、转台或登录命令。串口测试只验证端口可打开，不宣称已完成固件握手。USB 串口不承载照片；照片由以太网 UDP 传输。
3. 接收器保存原始照片和元信息；有结束标记、正确收发计数、完整位置及帧质量后，后台自动导入为新任务。同一轮不会因刷新页面或重启重复导入。未齐的采集、单张预览不进入自动建模输入。
4. 最新实机已收到 **18 张主摄照片**，程序按实际计划检查，同时兼容旧版 162 张，不固定要求 36 张。后续 **主摄 18＋顶部 18** 也已加入电脑端解析；板端需提供相机身份、位置和唯一图像序号，见 `config/双摄接入协议.md`。本次未修改 FPGA 固件。
5. 当前 FPGA 主摄以倒数第二张为正面；18张时为第17张，双摄仅在主摄序列内计数。灰模有三种选图方式：快速预选根据完整采集顺序估计四方向（假定一圈均匀转动，不是实测角度）；手选四方向直接建灰模；先配准计算方向更慢，但用几何估计方向。普通文件夹没有可信位置序列，需要手选或配准。快速预选由 `capture_order_direction` 指定递增序列朝向（当前为 left）；反向旋转应改为 right 或手动改选四张。明确四方向输入清单优先，已有手选在页面重新打开后保留。
6. 点击“生成灰模”后，分割前景、GPU推理形状并导出。勾选“建灰模时同时准备照片贴图”，则CPU相机配准与GPU形状生成并行；灰模先完成就先展示和允许下载，配准失败只影响照片上色。取消勾选可在快速预选或手动模式下完全跳过配准；以后点“生成彩色模”再计算。也可选择“一次生成灰模和彩色模”，上色失败仍保留灰模。前景为空、方向重复或缺失、GPU失败仍正常报错，不保证任意四张都能生成正确形状。
7. 页面展示同一正面视角的实际处理结果：**原片 → 主体掩码 → 去背景图 → 模型实际的 512×512 输入**。掩码白色表示保留，不按物体颜色去除白色。IS-Net 仍可能误分割，手动选项提供主体框和恢复/擦除画笔，修正后会保留本轮已核对的前景。
8. 进度条显示当前阶段实际完成量；匹配对数、8 步 GPU 推理有计数，加载、配准求解和解码显示等待状态。取消会终止本任务工作进程及其 COLMAP 子进程，不关闭其他软件。
9. 配准和模型对齐通过后，导出内嵌贴图的彩色 GLB、2048×2048 底色 PNG、彩色 OBJ 套件（含 MTL 和图像）、覆盖检查图与报告；保留灰模 GLB、2.4 万面目标的轻量灰模、OBJ、PLY。自动贴图失败则保留灰模并显示原因。导出成功不等于结构通过人工验收，仍需旋转检查。AI 几何含推断，无实测尺寸、骨骼、蒙皮或动画拓扑保证。
10. 硬件未接入时仍可导入已有照片离线运行。带支持的 `manifest.json` 会核对采集和哈希；普通文件夹不声称整轮完整。原片、旧任务及每次模型输出独立保存。

## 本版范围

这是从实验工程提取的可重复使用的 **照片接收 + 四方向 AI 形状生成 + 多视角照片 UV 贴图** 入口。不会将此前针对某次拍摄的相机位姿、固定人物裁剪框用于新物体。先前的彩色精修模型可从界面单独查看，但未冒充新任务输出。

新的照片贴图步骤使用本轮独立计算的相机位置，全局相似变换对齐 AI 形状与照片轮廓，用 xatlas 展开 UV，再经过遮挡、前景、观察角度和清晰度检查，把原片颜色投影到网格。新版按网格邻接关系选择连续照片区域，并只在共享颜色验证通过后进行有限曝光校正。展示版对没有观测的区域采用沿网格表面的邻近颜色插值；仅照片版仍保留中性灰。该补色不使用生成式 AI，不恢复未拍到的图案。轮廓一致不能证明内部五官、头发等细节一致。旧工程的专用轮廓变形和 OpenMVS 流程仍独立保留。本次扩展了现有接收元信息，使电脑端区分双摄，保留旧单摄协议。双摄目录也可通过带完整清单的文件导入。

当前形状网络是 **Hunyuan3D-2mv 四方向模型**，只直接输入选中的四张；不能声称 162 张或 36 张都进入了形状网络。其他已配准照片用于方向计算、投影核对和颜色贴图，不会自动获得多视角实测深度。

## 源码、运行环境与迁移

- `server.py`、`studio/`、`web/`：连接、照片任务、进度、交互和导出入口。
- `tools/`：前景分割、GPU 生成、网格导出、模型下载工具。
- `vendor/fpga/`：已修复的接收协议；`vendor/hunyuan3d/`：固定版本及带修改说明的形状推理代码；`vendor/viewer/`：离线预览代码。
- `config/default.json`：可迁移默认参数；`config/local.json`：仅当前电脑路径，不能上传。
- `licenses/`：保留第三方许可和修改记录；不把整个工程统一改成 MIT 许可。
- `data/`：运行产生的照片、模型、日志与任务（本机当前数据目录为 `data/reliable_color/`，旧 `data/front_color_fix/` 与 `data/release/` 完整保留）；不进源码压缩包或 GitHub。

当前电脑的桌面服务和照片接收使用本目录独立的 `runtime-ui` 环境，启动时检查依赖，并禁用用户包目录加载，避免依赖聊天应用缓存。AI 推理和分割仍使用原 GPU 工程的环境和模型权重。**所以本机不要删除 `runtime-ui`、原 `GPU加速版/environment` 和 `advanced` 中使用的权重。** 精简源码包不含这些运行环境、大权重或照片成品。

桌面入口同时点击或重复打开会复用已就绪的服务。启动诊断保存到实际数据目录的 `launcher.log`，Python 服务错误保存到 `server_error.log`；缺少依赖时会显示具体模块。启动成功与 FPGA 已连通分别判断，开发板未接入时仍可打开软件、离线处理照片。

在另一台 Windows 电脑：解压源码包，安装 Python 3.11 和支持 CUDA 的 NVIDIA 驱动，在 PowerShell 运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1`。安装脚本创建本目录独立 `runtime`，安装固定依赖，下载并验证 Hunyuan 约 4.93 GB 与 IS-Net 约 179 MB 的权重，再创建桌面快捷方式。下载及首次安装耗时不算建模时间。迁移安装脚本尚需在新机器上验证，不宣称任意电脑开箱即用。

自动计算方向另需 **COLMAP CUDA** 可执行文件及 **SuperPoint＋LightGlue ONNX** 模型。默认迁移包不捆绑这两个组件；在 `config/local.json` 设置 `colmap` 与 `matching_model` 的完整路径。缺少配准组件时，桌面彩色流程会在 GPU 前停止并提示配置；手选四方向不能替代相机配准。底层四图形状工具仍独立可用，但不等于能生成照片贴图。模型下载源、大小与哈希见 `config/lightglue_source.json`，可运行 `python tools/download_models.py --matching-only` 下载匹配权重。COLMAP 请使用支持 `SiftExtraction.use_gpu`、`SiftMatching.use_gpu` 与 `Mapper.ba_use_gpu` 的兼容版本。本机版本已验证，其他版本未保证参数兼容。

仅关闭界面窗口不会中断正在接收或建模的任务。停止接收或取消任务请用界面按钮；重复打开桌面入口会复用服务，并重新检测连接。

## GitHub 上传

上传源码包内的文件即可；`.gitignore` 排除本机配置、权重、环境、照片、模型和日志。权重按有 SHA256 的下载清单获取。当前工作未创建或推送 GitHub 仓库。若要公开分发，还需遵循 `licenses/Hunyuan3D_LICENSE.txt` 的许可和地域条件，不应作为无限制 MIT 工程发布。

## 验证

使用已安装依赖的解释器运行测试；纹理几何与选图测试需要 AI 环境的 SciPy，轻量 UI 环境会跳过该项选图测试。本机可运行 `runtime-ui\Scripts\python.exe -s -m unittest discover -s tests -v`。本机实时连接、UI 和 GPU 完整流程的实测结果见随附验证说明；模拟 UDP 测试不等于真实 FPGA 传输成功。

## 单圈 18 张颜色实验（2026-11-02）

本轮从旧照片中，依据已有估计角度选择覆盖一圈的 18 张主摄原片；此前位姿只用于选片。新任务完全从这 18 张重新配准，没有将其他照片或顶部照片投入本次建模、对齐或贴图。`tools/select_ring_subset.py` 保存选片角度、原片哈希和来源。18 个目标方向间隔 20°，实际可用照片的角度并不精确等分。

完整一键复测：227.03 秒（含配准、生成、贴图、导出，贴图阶段 78.82 秒），不含拍摄和导入。第一轮分段实验：18/18 配准，灰模流程 115.33 秒，贴图 67.51 秒；18 张中选出的 4 张进入形状网络。2048 贴图的有效 UV 像素约 92.4% 有颜色观测，约 7.6% 无观测；这不是表面积或准确率。正侧面已有颜色，顶部可见大块未覆盖区域，肩部与发丝仍有错位接缝。保留顶部采集能力有价值；需要多少张顶部照片必须实拍验证，不能由本次单圈实验确定。

该次历史实验界面运行在 `http://127.0.0.1:8792/`，数据目录 `data/color18`。为避免影响用户固化 FPGA，当时使用 `python server.py --offline-start --port 8792 --data-dir data/color18`，不在启动时探测串口或接收端口。2026-11-03 更新后桌面入口已指向 8793；早期实验地址不代表当前版本。

## 底座与手动贴图流程修复（2026-11-02 晚）

- 手动选图、输入四方向清单、检查前景后的建模，均先检查本轮配准及输入版本；不再跳过配准后必然贴图失败。失败信息显示具体原因。
- 自动模式尊重当前正面卡片的参考照片，重新计算侧面和背面；手动四方向会验证角度，错误时在 GPU 前停止。
- 主体框统一用于本轮同一主摄的候选分割、四图输入和照片贴图；侧面单独框优先，不传播给顶部或其他轮次。原图带透明通道时也遵守主体框。
- 全部输入照片中可为每张照片添加背景排除框、清除该照片排除框。适合去掉转台、标定块等干扰；框内像素不会进入形状或贴图。保存于该任务 `background_regions.json`，不是按白色、固定身高或物体类别删除。
- 无法保证 IS-Net 自动区分物体和相连底座。底座、支架或标定块混入时应检查预览，框选完整主体或排除背景；换物体必须重新检查。遮挡住物体的像素不能从该张照片恢复。

## 2026-11-03 灰模独立生成与并行照片配准

旧流程将完整相机配准当作灰模的硬性前置条件。新采集虽有正侧背面，COLMAP未成功注册四张参考，导致手选也被拦截。本版分开了这两个依赖：四方向图片驱动AI形状；相机配准负责验证角度和为照片贴图提供投影关系。

- 灰模只要求四张不同的方向输入、有效前景和可用GPU。自动预选只是名义方向估计，有偏差时请改选；不会伪造相机参数来通过照片贴图。
- 并行配准在每次运行独立的 `registration` 目录读取原片与选图快照，使用CPU，不改动正在生成灰模的输入和网格。通过后保存相机和掩码快照；失败不删除灰模，不误报灰模失败。
- “建模进度”分别显示灰模与照片贴图配准状态。灰模完成后即能预览和下载，后台配准继续。取消会停止本次所属子进程；已保存的灰模不删除。
- 单独上色时，如果灰模没有配准快照，会用该灰模的原始选图/照片记录重新计算配准，保留原模型；不能用后来改选的照片悄悄给旧模型上色。

## 2026-11-03 可靠视角照片贴图与转台约束

当前入口8795，数据 `data/reliable_color/`。沿用灰模先生成、照片配准独立进行的设计，旧数据保留。单独上色会复用当前灰模，并使用该次形状输入保存的照片/前景记录。

1. 主体完整掩码与参与匹配的区域分开。只对特征描述输入屏蔽掩码外的背景上下文；输出主体掩码、灰模和原始照片不因此裁切，不按白色去掉主体。配准采用SuperPoint/LightGlue和COLMAP几何验证。
2. 每张照片检查可靠特征数、重投影误差。页面显示角度分布、逐图诊断和匹配点示例，可下载详细报告；此误差不等于独立标定精度。
3. 对明确启用 `turntable_calibration` 的固定相机转台场景，普通SfM失败后可尝试共同转轴、固定距离的束调整。逐帧角度由图像残差优化，采集编号只作为初值；不会把名义20度伪装成实测转角。整体特征轨迹留出用于验证，每个视角按预测误差决定是否参与贴图，并报告首尾轨迹连接数和反向角度异常。当前该备用求解只支持单主摄，本机开启，通用默认配置关闭；双摄仍走原联合SfM。

## 2026-11-03 前景误删修复

原版 IS-Net 只看主体框，一次分割后直接二值化，会把浅色肩臂、手套或带状装饰误删。照片文件本身未改动。现在同时参考主体框及两级周边范围，保留与原主体连接的补充识别区域，再用原尺寸 RGB 的图割校正不确定边缘。主体框与明确的背景排除框仍是输出边界；不会把扩大观察范围直接当成新的主体范围。

这套处理不写死人体部位，不以白色或亮度作为删除条件，不做凸包、统一膨胀或强制填孔。原片 RGB 不变，输出 PNG 的透明掩码变化。照片配准仍单独使用向内收缩的特征掩码。分割与配准缓存带处理版本，旧版本方向缓存不直接当作新版前景使用。

已生成的旧灰模不会因修改图片自动修复；应重新处理图片并生成灰模，然后再上色。仅点击“生成彩色模”会保留原灰模几何。用户画笔修正的前景继续由用户控制。
